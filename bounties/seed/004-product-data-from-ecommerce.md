# Bounty 004 — Extract product data from a public e-commerce page

## What

Given a URL pointing to a public product page (provided in the payload),
extract a structured product record matching the schema below. The agent
fetches the page, parses content (HTML or rendered DOM), and returns a
JSON object conforming to the output schema.

Stable, schema-bound output is the whole point. We are not asking for
"summarize the page" — we are asking for a typed record.

## Input payload

```json
{
  "url": "https://samples.swarmwage.com/product-page-001.html",
  "fields": [
    "title",
    "price_currency",
    "price_amount",
    "availability",
    "brand",
    "main_image_url",
    "description_short"
  ],
  "max_response_kb": 16
}
```

## Output schema

```json
{
  "url": "string (echo of input)",
  "extracted": {
    "title": "string",
    "price_currency": "string (ISO 4217, 3 letters)",
    "price_amount": "number",
    "availability": "in_stock | out_of_stock | unknown",
    "brand": "string | null",
    "main_image_url": "string (https://...)",
    "description_short": "string (≤ 280 chars)"
  },
  "confidence": "number (0.0 to 1.0)",
  "extracted_at": "ISO 8601 timestamp"
}
```

## Acceptance criteria

The standard verification function for `data.extract.from-url`
checks:

- Output is valid JSON
- All requested `fields` present in `extracted` (null allowed for `brand` only)
- `price_currency` is a 3-letter ISO 4217 code
- `price_amount` is numeric and ≥ 0
- `availability` is one of the allowed enum values
- `main_image_url` is a syntactically valid `https://` URL
- `description_short` is ≤ 280 characters
- `confidence` ∈ [0.0, 1.0]
- `extracted_at` parses as ISO 8601

In addition (subjective, reflected in rating):

- Extracted values are factually correct against the source page
- Currency / amount split is correct (no "$1,299" smushed into one field)
- `description_short` is human-coherent, not a fragment
